Predicting Parkinson's True Motor Score

What we tried · What failed · What worked · Why
The Problem

The dataset contains clinical visits for 5,576 Parkinson's patients. The goal: predict the debiased true-OFF MDS-UPDRS motor score — a synthetic target that removes the bias introduced by drug timing, measurement subjectivity, and missing exams. Test patients are completely unseen — different people from training data.

Training data
44,590 visits · 5,576 patients
Test data
11,013 visits · 1,395 new patients
Key constraint
No patient overlap train ↔ test → GroupKFold CV mandatory
Strongest raw signal
off score (r = 0.886) — but 42% missing
The Journey — What We Tried
Baseline — Ridge + median imputation CV 10.44
Standard starting point: impute missing values with median, fit Ridge.
Median imputation erases signal — off = NaN means the patient skipped the OFF exam because they were doing well. That's information, not noise.
NaN-native trees — HistGradientBoosting CV 7.44
HGBR routes missing values to a separate branch instead of filling them. Single biggest jump: −29% over Ridge.
The model learned that rows where off is missing are systematically different patients (earlier stage, doing better on medication). This is a real clinical signal.
Feature engineering — disease duration, on/off gap CV 7.37
Added disease_duration = age − age_at_diagnosis and categorical encoding via skrub's TableVectorizer.
Marginal but consistent improvement. The real ceiling was that we weren't using the longitudinal structure of the data — patients have 4–12 ordered visits.
Cumulative patient history features CV 4.14 Kaggle 22.50 ❌
Built expanding cumulative max/mean of each patient's prior off, on, ledd scores. CV looked great. Kaggle was a disaster.
The distribution shift trap. The final model was fit on all 44k training rows — where every patient already has rich cumulative history (visits 2–8 are all populated). But test patients are brand-new: their cumulative features are NaN-sparse for early visits. The model trained on dense features and was asked to predict on sparse ones. GroupKFold CV was accurate (it also saw NaN-sparse early visits) but the final fit on all data was a different, overconfident model.
Strategy 2 — demographic progression (no history) CV 7.34 Kaggle: best at the time ✅
Stepped back: cross-sectional features only — on, off, ledd, demographics, on_off_gap. No lags. No history. No shift.
Every feature is equally observable for a brand-new test patient at visit 1 or visit 8. The honest model.
Off-corrected formula model CV 4.06 Kaggle 3.968 ✅ Best
Incorporated a clinically-grounded correction before any feature computation, then used cumulative history of the corrected scores — safely.
Key insight: the target is always ≈ off + 8. Once the correction is baked in, even visit-1 patients get a meaningful prior estimate. Cumulative history of corrected scores is informative from the start — no cold-start collapse.
Why the Winning Model Works

The competition target is a debiased true-OFF score. Measured off systematically understates it because levodopa is never fully washed out. The generative model in the data is approximately:

target = off + levodopa_residual_correction   (always positive)
target ≈ off + 8.0   at long washout (>12 h)
target ≈ on + levo_conc_on   when off exam is missing
Mean off = 17.4, mean target = 21.3 for off-only rows — gap of ~3.9 on average, but the correction grows with levo dose and timing.
Key feature 1
off + 8
off_corrected — removes the systematic levodopa bias before any cumulative computation. Informative at visit 1 even without history.
Key feature 2
on + conc
on_corrected — pharmacodynamic debiased estimate when off is missing. Unifies both exam types into one signal.
Key feature 3
2 populations
Exam-type flags has_off, has_on_only — OFF patients are early-stage (target ≈ 21), ON-only patients are later-stage (target ≈ 44). Explicit segmentation.
Key feature 4
safe history
Cumulative max/mean/prev of corrected scores (shift + expanding). Safe at test time because corrected base values are non-NaN from visit 1.

Key Lessons
  • 1 Missingness is signal, not noise. In a clinical dataset, a missing OFF exam typically means the patient felt well enough to skip it. Imputing destroys that. Use NaN-native models.
  • 2 GroupKFold is necessary but not sufficient. CV can look honest while the final fit on all data creates a completely different feature distribution than what's seen at test time. Always verify that feature sparsity matches between train and test.
  • 3 Read the data-generating process. The competition explicitly states the target is a debiased true-OFF score. Once we modelled that explicit correction (target ≈ off + 8), the entire feature engineering strategy clicked into place.
  • 4 Cold-start is the fundamental test challenge. Any feature that requires prior patient history collapses for new patients. Either avoid history entirely, or anchor it in corrections that are informative from the very first visit.
