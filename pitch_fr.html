Le problème médical

Les patients atteints de la maladie de Parkinson oscillent entre un état ON (médicament efficace) et OFF (médicament épuisé). Le score OFF clinique est biaisé : subjectivité humaine, timing du médicament, examens souvent évités car inconfortables. La compétition demande de prédire le vrai OFF débiaisé — une cible synthétique qui retire ces biais.

⚠️ Les NaN sont du signal, pas du bruit — off=NaN signifie souvent que le patient allait trop bien pour subir l'examen.

Contrainte clé — cold-start total

Les patients de test sont entièrement inconnus. Toute feature calculée depuis l'historique d'entraînement (prev_target, cumulatif dense) est NaN au test. C'est le piège central de la compétition — il a valu un RMSE Kaggle de 22.50 sur l'exp09b malgré un CV à 4.13.

Chemin des décisions

1
Dummy → Ridge (exp 01–03) RMSE 16.50 → 10.44
La médiane impute les NaN et détruit le signal "patient absent = allait bien". Ridge plafonne à 10.4 — bottleneck de forme, pas de régularisation.
2
HGBR + skrub TableVectorizer (exp 04–07) RMSE 7.44 → 7.37
HGBR route les NaN dans des branches séparées → le NaN est le signal. gene/cohort encodés. disease_duration ajouté.
3
Cumulatif brut — le piège (exp 09b) CV 4.14 → Kaggle 22.50 ❌
Fit final sur 44k lignes (cumulatif dense) puis prédiction sur patients test (cumulatif sparse). Distribution shift sévère. CV était précis mais le modèle final ≠ modèle CV.
4
off_corrected = off + 8 (exp 11) CV 4.06 / Kaggle 3.968 ✅
Découverte clé : target ≈ off + 8 à long washout. Cumulatif calculé sur scores corrigés — même à la visite 1, off_corrected est informatif.
5
Agrégats whole-patient + régression linéaire (exp 16) CV 3.47 / Kaggle ~3.5
Features calculées sur toutes les visites du patient (passées + futures) depuis X uniquement : pente/intercept de off_corrected ~ disease_duration, moyenne LOO, proportion de visites avec OFF mesuré.
6
whole_patient_v2 — 5 seeds + lissage polynomial auto (exp 17) Kaggle 3.246 🏆
Ensemble de 5 seeds HGBR. Lissage polynomial par patient (degré 1/2/3 selon le nombre de visites). Blend 50/50 avec exp16. Meilleur résultat.

Formule du meilleur modèle (exp 17)

// Correction pharmacodynamique
off_corrected = off + 8.0
levo_conc_off = ledd × exp(−0.05 × time_since_intake_off)

// Agrégats whole-patient (toutes visites, X seulement)
pat_slope_off = pente(off_corrected ~ disease_duration) par patient
pat_fitted_off = slope × disease_duration + intercept
pat_offc_loo_mean = moyenne LOO de off_corrected par patient
pat_frac_off = fraction de visites avec off mesuré

// Modèle
TableVectorizer + HGBR(1000 arbres, lr=0.02, 5 seeds)
→ lissage polynomial auto-degré par patient
→ blend 50/50 avec exp16
→ RMSE Kaggle 3.246

Enseignements clés

1
target ≈ off + 8 — Le score cible est systématiquement ~8 points au-dessus du off mesuré à long washout. C'est le biais central que la compétition demande de corriger.
2
Deux populations distinctes — Patients avec off mesuré (début de maladie, target ≈ 21) vs patients ON-only (maladie avancée, target ≈ 44). Les flags has_off/has_on_only sont essentiels.
3
GroupKFold nécessaire mais insuffisant — GroupKFold évite la fuite patient en CV. Mais si le fit final crée une distribution de features différente (cumulatif dense vs sparse), le CV est trompeur. Toujours vérifier que clone(model).fit(X_full) prédit sur les mêmes distributions.
4
Les features whole-patient sont valides au test — Calculer la pente de progression, la moyenne LOO et la fraction OFF sur toutes les visites d'un patient (sans toucher la cible) donne des features très informatives, identiquement disponibles sur train et test.
5
Ensemble + lissage polynomial — Moyenner 5 seeds réduit la variance. Le lissage polynomial par patient (degré auto selon le nombre de visites) lisse les prédictions incohérentes inter-visites.
